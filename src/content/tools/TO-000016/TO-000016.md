# BYTEROVER 知识管理

使用 `brv` CLI 来管理项目的长期记忆。知识以人类可读的 Markdown 文件形式存储在 `.brv/context-tree/` 目录中。

**安装：** `npm install -g byterover-cli`

无需认证。`brv query`、`brv curate` 和 `brv vc`（本地版本控制）开箱即用。只有在进行远程同步（`brv vc push`/`brv vc pull`）时才需要登录。

---

## 工作流程

1. **思考前：** 运行 `brv query` 了解现有模式
2. **实现后：** 运行 `brv curate` 保存新的模式/决策

---

## 命令

### 1. 查询知识

**概述：** 从项目知识库中检索相关上下文。使用配置的 LLM 提供商从 `.brv/context-tree/` 内容综合答案。

**何时使用：**
- 用户希望你回忆某些内容
- 当前上下文中缺少所需信息
- 需要回忆能力或过去的行为
- 在执行任何操作之前，检查相关规则、条件或偏好

**何时不用：**
- 信息已存在于当前上下文中
- 查询的是通用知识，而非存储的记忆

```bash
brv query "How is authentication implemented?"
```

### 2. 搜索上下文树

**概述：** 通过纯 BM25 检索从 `.brv/context-tree/` 获取匹配文件排名列表。与 `brv query` 不同，此命令**不**调用 LLM——无综合、无 token 成本、无需提供商设置。返回包含路径、分数和摘录的结构化结果。

```bash
brv search "authentication patterns"
brv search "JWT tokens" --limit 5 --scope "auth/"
brv search "auth" --format json
```

### 3. 整理上下文

**概述：** 分析并将知识保存到本地知识库。使用配置的 LLM 提供商对提供的上下文进行分类和结构化。

**何时使用：**
- 用户希望你记住某些内容
- 用户有意整理记忆或知识
- 用户交互中有意义且应持久化的记忆
- 关于你做什么、你知道什么、或已采取的决策和行动的重要事实

```bash
brv curate "Auth uses JWT with 24h expiry. Tokens stored in httpOnly cookies via authMiddleware.ts"
```

**包含源文件（最多 5 个，仅限项目范围）：**

```bash
brv curate "Authentication middleware details" -f src/middleware/auth.ts
```

### 4. LLM 提供商设置

`brv query` 和 `brv curate` 需要配置 LLM 提供商。连接默认的 ByteRover 提供商（无需 API 密钥）：

```bash
brv providers connect byterover
```

使用其他提供商（如 OpenAI、Anthropic、Google），列出可用选项并使用自己的 API 密钥连接：

```bash
brv providers list
brv providers connect openai --api-key sk-xxx --model gpt-4.1
```

### 5. 项目位置

**概述：** 列出已注册项目及其上下文树路径。返回项目元数据，包括初始化状态和活跃状态。

```bash
brv locations -f json
```

### 6. 版本控制

**概述：** `brv vc` 为上下文树提供基于 git 的版本控制。使用标准 git 语义——分支、提交、合并、历史和冲突解决——全部在本地运行，无需认证。

#### 首次设置

**设置 —— 本地（无需认证）：**

```bash
brv vc init
brv vc config user.name "Your Name"
brv vc config user.email "you@example.com"
```

#### 本地工作流

**检查状态：**

```bash
brv vc status
```

**暂存和提交：**

```bash
brv vc add .                     # stage all
brv vc add notes.md docs/         # stage specific files
brv vc commit -m "add authentication patterns"
```

**查看历史：**

```bash
brv vc log
brv vc log --limit 20
```

## 数据处理

**存储：** 所有知识以 Markdown 文件形式存储在项目目录的 `.brv/context-tree/` 中。文件人类可读且可版本控制。

**文件访问：** `brv curate` 上的 `-f` 标志仅从当前项目目录读取文件。项目根目录外的路径会被拒绝。每个命令最多 5 个文件，仅支持文本和文档格式。

**LLM 使用：** `brv query` 和 `brv curate` 将上下文发送到配置的 LLM 提供商进行处理。LLM 会看到查询或整理文本以及任何包含的文件内容。

---

## 错误处理

**用户需处理：** 发生错误时必须向用户显示此故障排除指南。

| 错误 | 解决方案 |
|------|----------|
| "Not authenticated" | 运行 `brv login --help` 了解详情 |
| "No provider connected" | 运行 `brv providers connect byterover`（免费，无需密钥） |
| "Connection failed" / "Instance crashed" | 用户应终止 brv 进程 |
| "Token has expired" / "Token is invalid" | 再次运行 `brv login` 重新认证 |
| "Billing error" / "Rate limit exceeded" | 用户应检查账户额度或等待后重试 |

## 快速诊断

运行 `brv status` 检查认证、项目和提供商状态。
